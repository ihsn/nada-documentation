# Community

Use the [NADA GitHub repository](https://github.com/ihsn/nada) to follow releases, report problems, and suggest improvements.

## Get notifications from GitHub

GitHub can notify you about activity on the NADA repository, including new releases.

1. Open [https://github.com/ihsn/nada](https://github.com/ihsn/nada).
2. Click **Watch** near the top of the page (it may show **Unwatch** if you already follow the repository).
3. Choose **All Activity**.

![GitHub Watch menu on the NADA repository, with All Activity selected](/images/github-watch-menu.png)

This is the simplest option: you will be notified about releases, issues, pull requests, and other repository activity.

If you only want emails about new NADA versions, choose **Custom** in the same menu, select **Releases**, then click **Apply**.

![GitHub Custom watch options, including Releases](/images/github-watch-custom.png)

You can change or turn off Watch settings at any time from the Watch menu.

### Star vs Watch

| Action | What it does |
|--------|----------------|
| **Watch → All Activity** | Notifies you about releases and other repository activity (easiest option) |
| **Watch → Custom → Releases** | Notifies you only when a new version is published |
| **Star** | Bookmarks the repository on your GitHub account. It does **not** send emails |

## Releases and downloads

Published versions, release notes, and downloadable packages are listed on the [NADA releases page](https://github.com/ihsn/nada/releases).

## Report a bug

If something does not work as expected:

1. Check [existing issues](https://github.com/ihsn/nada/issues) to see if it was already reported.
2. Open a [new issue](https://github.com/ihsn/nada/issues/new) on GitHub.
3. Include the NADA version, your environment (OS, PHP, database), and steps to reproduce the problem.

## Suggest a feature

To propose an enhancement or new capability, open a [GitHub issue](https://github.com/ihsn/nada/issues/new) and describe:

- The problem you are trying to solve
- Who would benefit
- Any ideas for how it could work

Clear use cases help maintainers prioritize requests.
